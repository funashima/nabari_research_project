# なばり情報システム

名張市役所と名張市観光協会のお知らせを、ひとつの画面から探せるWebアプリです。暮らしの情報や観光・イベントの案内を集め、見出しと短い抜粋を表示します。詳しい内容は、各記事のリンクから公式ページで確認できます。

高専の研究プロジェクトとして制作した試作システムです。名張市役所・名張市観光協会の公式サービスではありません。

このREADMEでは、初めて使う人に向けて、準備・起動・操作・保存方法を説明します。コマンド例はUbuntuなどのLinuxを想定しています。

## できること

- 市役所と観光協会のお知らせをまとめて検索する。
- 「イベント」「観光・お出かけ」「ごみ・資源」「健康・福祉」「相談」「防災」「くらし・手続き」で絞り込む。
- 情報の出典、掲載日・更新日、このアプリが取得した日時を確認する。
- 文字を大きくする、色の差をはっきりさせる、記事を読み上げる、印刷する。
- アプリを起動している間、定期的に公式サイトから情報を取得する。
- 同梱の取得済みデータで、通信せずに検索や表示を試す。

利用者登録や外部サービスのAPIキーは不要です。通常の利用では、Pythonコードを編集する必要もありません。

## しくみ

Pythonのプログラムが公式サイトからお知らせを取得し、パソコン内のデータベースに保存します。ブラウザで検索すると、Flaskが保存済みの情報から条件に合うページを作ります。

検索のたびに公式サイトへアクセスする仕組みではありません。情報の収集と、保存した情報の表示を分けています。新しく取得した情報を見るときは、ブラウザのページを再読み込みしてください。

## 必要なもの

| 必要なもの | 用途 |
| --- | --- |
| Python 3.11以上 | アプリを動かします。制作時はPython 3.12.14で動作確認しました。 |
| Webブラウザ | 検索や記事の閲覧に使います。 |
| インターネット接続 | 初回のライブラリ導入と、公式サイトからの情報取得に使います。 |
| 配布ZIPを展開したフォルダ | `README.md`、`run.py`、`requirements.txt`などが入っています。 |

アプリの利用にNode.jsやLaTeXは不要です。LaTeXは、同梱の報告書の原稿を編集してPDFを作り直す場合にだけ使います。

## 初回の準備

### 1. ZIPを展開する

`nabari_research_project.zip`を展開し、このREADMEと`run.py`が同じ場所にあることを確認してください。

そのフォルダで端末を開きます。以降のコマンドは、特に断りがない限り、このフォルダで実行します。コード欄のコマンドを、上から順に入力してください。

### 2. Pythonを確認する

```bash
python3 --version
```

`Python 3.11`以上であることを確認します。UbuntuでPythonや仮想環境の機能が入っていない場合は、次のコマンドで準備できます。

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip
```

### 3. このアプリ用の環境を作る

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

`.venv`は、このアプリが使うライブラリをまとめて置くフォルダです。2行目のコマンドで、その環境を使うように切り替えます。ライブラリの導入にはインターネット接続が必要です。

## 起動する

### 通常の起動：公式サイトから情報を取得する

準備が終わった端末で、次を実行します。

```bash
python run.py
```

続いて、ブラウザで次のアドレスを開きます。

**<http://127.0.0.1:8000/>**

`127.0.0.1`は、いま使っている自分のパソコンを表すアドレスです。初期設定では、そのパソコンから閲覧します。

起動直後に情報の取得が始まります。初回はまだ記事がないため、表示まで少し時間がかかります。画面下部の「収集状況」で進み具合を確認できます。通常は両方の出典の収集が終わってから30分待ち、次の収集を始めます。

**起動した端末は、そのまま開いておいてください。** ブラウザを閉じてもアプリは動き続けますが、端末でアプリを終了すると、閲覧と定期収集の両方が止まります。

### 終了する・次回また起動する

終了するときは、アプリを起動した端末で **Ctrl+C** を押します。取得済みの情報はパソコン内に残ります。

次回は同じフォルダで、次の2行を実行します。環境の作成やライブラリの導入を毎回やり直す必要はありません。

```bash
source .venv/bin/activate
python run.py
```

## まず取得済みデータで試す

公式サイトへの通信を行わず、画面の操作だけを試す方法です。初回のライブラリ導入を済ませた後に利用できます。通常起動のアプリが動いている場合は、先にCtrl+Cで終了してください。

通常の保存先とは別の`instance/demo.sqlite3`を使うため、すでに集めたデータと混ざりません。

```bash
source .venv/bin/activate
NABARI_DATABASE=instance/demo.sqlite3 python -m flask --app nabari import-demo
NABARI_DATABASE=instance/demo.sqlite3 python run.py --no-collect
```

ブラウザで **<http://127.0.0.1:8000/>** を開きます。

- デモには、2026年9月29日に実際に取得した30件の情報を使います。現在の最新情報ではありません。
- 「最終取得日時」は、デモを読み込んだ日時ではなく、元の情報を取得した日時です。
- デモの取り込みは初回だけ行います。同じ保存先に記事がある場合、上書きを防ぐため取り込みを拒否します。
- 2回目以降は、仮想環境を有効にし、`NABARI_DATABASE=instance/demo.sqlite3 python run.py --no-collect`で起動できます。
- 検索や表示は通信なしで使えますが、公式ページを開くには通信が必要です。読み上げの利用可否はブラウザや音声環境によります。

通常の利用に戻すには、デモをCtrl+Cで終了し、`python run.py`で起動します。

## 画面の使い方

### 情報を探す

1. 「言葉で探す」に、`ごみ`、`相談`、`秋祭り`などの言葉を入力します。
2. 必要に応じて「情報の出典」と「カテゴリ」を選びます。
3. 「探す」を押します。
4. 気になる記事の見出しを押すと、詳細が開きます。
5. 詳しい内容は「公式ページへ」から確認します。

条件を元に戻すには「条件を解除」を押します。記事が多い場合は「次のページ」で続きを表示できます。

検索は主に見出しと短い抜粋を対象とします。全文検索ではありません。空白で複数の言葉を区切ると、すべての言葉を含む情報を探します。見つからないときは、言葉を短くするか、出典・カテゴリの条件を外してください。

### 読みやすくする

| 操作 | 内容 |
| --- | --- |
| 「標準」「大きく」「もっと大きく」 | 文字の大きさを変えます。 |
| 「色をはっきり」 | 文字と背景の色の差を強めます。もう一度押すと戻ります。 |
| 詳細画面の「抜粋を読み上げる」 | 記事の見出しと抜粋を音声で読みます。環境によって使えない場合があります。 |
| 「読み上げ停止」 | 読み上げを止めます。 |
| 「印刷する」 | ブラウザの印刷画面を開きます。 |

文字の大きさと色の設定は、利用中のブラウザに保存します。これらの調整や読み上げにはJavaScriptを使いますが、基本的な検索と記事の閲覧はJavaScriptを無効にしても利用できます。

## 日付と表示内容の読み方

| 表示項目 | 意味 |
| --- | --- |
| 出典 | 元の記事を公開している組織です。 |
| 掲載日・更新日 | 元の記事に記載された日付です。イベントの開催日とは限りません。 |
| 最終取得日時 | このアプリが、その記事を最後に取得した日時です。画面では日本時間で表示します。 |
| 自動分類 | 記事中の言葉を使って機械的に選んだカテゴリです。分類が合わない場合もあります。 |
| 本文冒頭の自動抜粋 | 抽出した本文の冒頭180文字までを表示します。長い場合は末尾に「…」を付けます。 |
| 保存後に検出した版 | 保存済みの記事について内容の変更を検出した回数に応じて増える番号です。初回は第1版です。 |

記事は、出典の掲載日・更新日の新しい順に並びます。開催日順ではありません。抜粋はAIが書き直した要約ではなく、元の記事の冒頭部分です。また、取得日時は人が内容を確認した日時ではありません。

次の点を踏まえて利用してください。

- 開催日時、申し込み条件、料金、休止・中止などは公式ページで確認してください。
- 古い記事も保存しています。表示されていることだけでは、イベントの開催中や申し込み受付中を判断できません。
- 最後の取得から24時間以上経過した記事の詳細には、確認を促す表示が出ます。
- 出典の日付が日本時間の今日より先の記事は、その日まで一覧・詳細・APIに表示しません。そのため、保存件数と表示件数が一致しない場合があります。
- このアプリは、災害警報などの即時性が必要な情報の確認には向いていません。

## どこから、どの範囲の情報を集めるか

| 出典 | 取得元 | 標準設定で1回に確認する範囲 |
| --- | --- | --- |
| 名張市役所 | [新着情報](https://www.city.nabari.lg.jp/news.html) | 一覧の先頭12件と、ごみ・保健・相談などの固定した7ページ |
| 名張市観光協会 | [お知らせ](https://kankou-nabari.jp/news) | 一覧の先頭12件 |

サイト内のすべてのページを取得するわけではありません。新着一覧から外れた記事も保存し続けますが、市役所の固定7ページを除き、一覧の対象範囲から外れた記事を継続して再取得する機能はありません。

保存するのは、見出し・短い抜粋・出典URL・日付などです。記事本文の全文、画像、PDFは再配信しません。取得先サイトの自動収集に関する指定を確認し、通信の間隔や1回の取得件数に制限を設けています。

## 収集がうまくいっているか確認する

画面下部の「収集状況」、または **<http://127.0.0.1:8000/status>** を開きます。

| 結果 | 意味 |
| --- | --- |
| 収集中 | まだ処理が続いています。時間を置いてページを再読み込みしてください。 |
| 完了 | その回の収集対象を取得できました。サイト内の全情報を取得したという意味ではありません。 |
| 一部失敗 | 取得できた記事と、取得できなかった記事があります。 |
| 失敗 | その回の収集を完了できませんでした。下部の詳細を確認してください。 |
| 収集記録なし | 収集履歴がありません。デモの取り込みだけを行った場合もこの表示になります。 |

履歴の「取得」は、その回の成功件数／対象件数です。「新規」は初めて保存した件数、「変更」は以前から内容が変わった件数、「同じ」は再取得した結果に変更がなかった件数です。「取得できなかった情報」を開くと、エラーや該当ページを確認できます。

通信に失敗しても、それまでに保存した記事は残ります。**記事が表示されることと、最新の情報を取得できていることは別です。** 取得日時も確認してください。

## よく使う設定

設定は、起動時のコマンドに付け加えます。実行中に変える場合は、いったんCtrl+Cで終了してから起動し直します。

| 設定 | 標準値 | 役割 |
| --- | --- | --- |
| `--port` | `8000` | ブラウザから接続する番号です。別のアプリと重なるときに変更します。 |
| `--interval` | `1800` | 1回の収集終了から次の収集までの待ち時間です。単位は秒で、`900`以上を指定します。 |
| `--limit` | `12` | 各新着一覧の先頭から取得する件数です。`1`〜`20`で指定します。市役所の固定7ページは別枠です。 |
| `--no-collect` | 指定なし | 付けると自動収集を行わず、保存済みの情報だけを表示します。 |

例：収集の間隔を約1時間にし、各新着一覧の先頭10件を取得します。

```bash
python run.py --interval 3600 --limit 10
```

例：8000番が使用中の場合は、8001番で起動します。

```bash
python run.py --port 8001
```

この場合、ブラウザで開くアドレスも **<http://127.0.0.1:8001/>** に変わります。

手動で1回だけ情報を収集することもできます。これらのコマンドは収集だけを行い、閲覧用のサーバは起動しません。

```bash
python -m flask --app nabari collect
```

観光協会だけを対象に、先頭8件を取得する例です。

```bash
python -m flask --app nabari collect --source tourism --limit 8
```

同じ出典への再収集は、前回の完了から15分以上空けます。自動収集と手動収集を重ねても、すぐに再取得されるわけではありません。

## データの保存とバックアップ

通常の保存先は`instance/nabari.sqlite3`です。必要なフォルダとデータベースは初回起動時に自動で作成します。アプリを終了してもデータは消えず、次回の起動で引き続き利用します。

バックアップする場合は、アプリをCtrl+Cで終了し、同じデータベースを使うほかの収集処理も止めてから、`instance`フォルダを別の場所へコピーしてください。稼働中に`.sqlite3`だけをコピーすると、保存内容の一部を取りこぼす場合があります。

`NABARI_DATABASE`で保存先を変えている場合は、変更後の保存先をバックアップします。デモ用の`instance/demo.sqlite3`と通常のデータベースは別のファイルです。

取得した記事と収集履歴を、共有・分析用のJSONファイルに出力するには、次を実行します。

```bash
python -m flask --app nabari export-data data/my_snapshot.json
```

このJSON出力にはすべての変更履歴が含まれるわけではなく、データベース全体のバックアップを置き換えるものではありません。指定したファイルがすでにある場合は上書きするので、残したいファイルとは別の名前にしてください。

## 困ったとき

| 状況 | 確認すること |
| --- | --- |
| `python`が見つからない | プロジェクトのフォルダで`source .venv/bin/activate`を実行してください。初回準備では`python3`を使います。 |
| 仮想環境を作れない／`ensurepip`のエラー | Ubuntuでは`python3-venv`が入っているか確認してください。 |
| `No module named flask`などが出る | 仮想環境を有効にし、`python -m pip install -r requirements.txt`を実行してください。 |
| `run.py`や`requirements.txt`が見つからない | ZIP展開後の`nabari-flask`フォルダで端末を開いているか確認してください。 |
| ブラウザで接続できない | `python run.py`が動いているか、端末にエラーがないか、アドレスとポート番号が正しいか確認してください。 |
| `Address already in use`が出る | 同じアプリを重複起動していないか確認します。必要なら`--port 8001`を使ってください。 |
| 記事が0件のまま | 初回収集の完了を待ち、ページを再読み込みします。検索条件を解除し、「収集状況」も確認してください。 |
| 最新の記事が見つからない | 取得日時、収集エラー、1回の取得範囲を確認してください。ページの再読み込みだけでは公式サイトからの収集は始まりません。 |
| デモの取り込みを拒否される | 指定した保存先に記事があります。すでにデモを取り込んでいるなら、取り込みを省略してデモを起動してください。 |
| 読み上げが動かない | 音量や日本語音声の利用可否を確認してください。検索・閲覧は読み上げなしでも使えます。 |
| 片方の出典だけ取得できない | 公式サイトをブラウザで確認し、収集状況のエラーを確認します。相手サイトの不調やページ構造の変更で失敗する場合があります。 |

取得先サイトの構造が変わった場合は、収集プログラムの修正が必要です。繰り返し起動しても直らない場合は、エラーメッセージと確認日時を記録して、運用担当者・開発担当者に伝えてください。

## 開発・研究に使う方へ

### 主なファイル

| ファイル・フォルダ | 役割 |
| --- | --- |
| `run.py` | 閲覧サーバと定期収集を起動します。 |
| `nabari/` | Flaskアプリ、情報収集、データ保存、画面の処理です。 |
| `data/` | 同梱の取得済みデータを置いています。 |
| `instance/` | 起動後に作られるデータベースの保存先です。配布ZIPには含めません。 |
| `docs/` | 報告書、解説書、運用手順、実験手順です。 |
| `tests/`、`tools/` | 自動テストや分析・文書生成用のプログラムです。 |
| `results/` | 制作時の取得結果と検証記録です。 |
| `dist/` | 予備実験用に残している旧試作画面です。通常のFlask画面とは別です。 |
| `deploy/` | 公開サーバへ配置する場合の説明です。 |
| `report_assets/` | PDF作成用のフォントと、そのライセンスです。 |

主なライブラリは、Web画面を作るFlask、情報を取得するrequests、HTMLを読み取るBeautiful Soup、アプリを配信するWaitressです。データ保存にはSQLiteというデータベースを、Python標準の`sqlite3`モジュールから使います。導入するバージョンは`requirements.txt`に記載しています。

### 自動テスト

通常の利用には不要です。コードを変更したときは、次のコマンドでPythonの自動テストを実行できます。

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

旧試作画面のJavaScriptテストを実行する場合だけ、Node.js 20以上を準備して次を実行します。

```bash
npm ci
npm test
```

検証記録は[results/verification_summary.json](results/verification_summary.json)にあります。利用者を対象とした評価実験は未実施です。画面の使いやすさが実証済みという意味ではありません。

`/research/`には、市役所の固定10件を使う旧試作画面の予備実験機能があります。

### 外部公開・データ連携

標準の起動方法は、自分のパソコンからの利用を想定しています。外部公開する場合の設定は[deploy/README.md](deploy/README.md)を参照してください。今回の配布物は、外部の公開サーバには配置していません。

保存済みの記事をJSONで取得するAPIは`/api/articles`、収集状況は`/api/collection-status`です。記事APIでは`q`、`source`、`category`、`page`を指定できます。`/healthz`はアプリとデータベースの応答確認用で、公式サイトへの通信成功を表すものではありません。

記事の出典は名張市役所と名張市観光協会です。記事・画像などの権利は各権利者に帰属します。記事等の再利用や収集範囲の拡大を行う場合は、各サイトの利用条件を確認してください。

同梱フォントのライセンスは[report_assets/OFL.txt](report_assets/OFL.txt)に記載しています。
