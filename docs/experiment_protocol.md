# 情報探索の比較実験 v1.0 — 固定UIの予備実験

状態：未実施。研究結果の数値はまだない。本書は実施手順である。

対象画面は `/research/` に置いた旧試作UIであり、市役所情報10件を固定して使う。Flask版の動的画面・観光協会情報を直接評価する実験ではない。Flask版の本評価では画面と課題を作り直し、観光協会の記事を含む固定スナップショットで条件をそろえる。

## 目的と仮説

研究質問は「同じ情報を提供した場合、カテゴリ・検索・要約を備えた画面は、単純な題名一覧より、IT操作に不慣れな利用者が必要な情報を探しやすいか」である。

主要指標は支援なしの正答率と、失敗等を180秒とした制限付き所要時間である。カテゴリ画面の正答率が高く、制限付き所要時間が短いという仮説を、両方向の差と95%区間で検討する。有意になるまで参加者や課題を増やさない。情報の地域網羅率やイベント参加増加は別の研究課題である。

## 参加者と準備

- 本試行の前に2〜4名で課題文と難しさを予備確認する。予備試行は `practice` とし、本試行へ混ぜない。
- 本試行の開始目標は16名（4群に4名ずつ）の探索的パイロットとする。これは検出力計算に基づく十分な人数ではない。予備試行後に対象・人数・中止条件を確定して日付を記録する。
- 対象は、日常のネット利用で手助けを要することがある成人を中心にする。高齢者を中心に調べる場合は年齢層を別途同意の下で記録し、若い学生だけの結果を高齢者へ一般化しない。
- 参加は自由で、途中で辞退してよく、成績や地域サービスに影響しない。研究担当者との力関係に配慮する。募集・録音・録画は本アプリでは行わない。
- 学校の研究倫理・個人情報管理のルールを担当教員に確認する。説明者の連絡先、保存場所、保存期限、撤回方法は実施前に具体的に決める。
- 氏名・住所・診断名・自由入力の検索語をアプリは記録しない。参加者番号はP001から連番にし、本人との対応表が必要なら記録ファイルとは別に管理する。

## 比較条件

- Enhanced：カテゴリ・検索・カード形式の概要・文字サイズ変更・配色変更を利用できる。
- Baseline：同じデータから同じ順序で題名だけを一覧表示する。詳細ページ、公式リンク、音声・印刷の内容は共通である。
- 両条件とも基準日を収録データの2026-09-29に固定する。イベントが時間経過で消えて課題が解けなくなることを防ぐ。普段の閲覧は実際の日本時間で判定する。
- 実験モードでは公式ページへの移動と実際の電話発信を止め、収録した本文の中から回答してもらう。外部情報の変化や実際の申し込みを実験に混ぜない。
- 比較実験は「市公式サイトとの優劣」ではない。画面全体の比較であり、カテゴリだけの因果効果を取り出す実験でもない。
- 端末・画面サイズ・入力機器・ブラウザ・音量・部屋の環境は参加者内でそろえる。ブラウザの標準ズームから開始し、必要な補助の利用は記録する。

## 順序と課題の割付

|参加者番号の組|前半3課題|後半3課題|
|---|---|---|
|P001, P005…|Enhanced / X|Baseline / Y|
|P002, P006…|Baseline / X|Enhanced / Y|
|P003, P007…|Enhanced / Y|Baseline / X|
|P004, P008…|Baseline / Y|Enhanced / X|

これは4群で順序と課題セットを釣り合わせる割付であり、無作為割付ではない。技能を見て都合よく番号を選ばない。課題セットの同等性は未検証なので、予備試行で確認する。前半・後半、群、課題ごとの結果も確認し、学習・疲労の可能性を報告する。

## 1人あたりの手順（約20〜30分）

1. 説明と同意を確認し、デジタル利用の自己評価・使用端末を記録する。実際の制度利用を申し込む実験ではないと伝える。
2. 両画面で、研究課題以外の「行政相談」を使い、題名を開く・戻る操作を1回ずつ練習する。練習は採点しない。検索・カテゴリ・文字拡大の存在も同じ定型文で紹介する。
3. `/research/` で `observed` を選び、参加者番号と端末情報を入力する。操作の練習中は `practice` を使う。
4. 評価者が課題を読み上げる。課題文の理解を確認して「開始」を押す。画面のデータ準備完了通知から計時する。読み込み中は時間に含めない。
5. 参加者が回答した時点で、正答と根拠の案内の確認を観察する。正しく支援なしで答えた場合のみ「正答・支援なし」を押す。誤答・断念は「誤答・断念」、探索上の助言が必要なら「支援あり」を選ぶ。
6. 180秒で自動的に時間切れを記録する。課題文の再読み上げは全員同じルールで許可し、答えにつながるヒントは支援として扱う。考えを話し続けることは求めない（時間への影響を避ける）。
7. 前半終了後に休憩と短い評価票を実施し、後半も同じ条件で行う。正答パネルは参加者に見せない。画面共有時は評価者用部分を隠す。
8. 6課題終了後にJSONを保存する。途中中断でも保存し、未完了者数と理由を匿名のメモに残す。ページを閉じると未保存の記録は消える。
9. 使いやすさ・困った場面・欲しい情報を聞き取る。固有名詞や個人の生活事情は必要以上に記録しない。次の人はページを開き直す。

## 指標と分析

各条件3課題のうち、支援なしの正答数を3で割ったものを参加者の正答率とする。時間指標は、正答なら実時間、失敗・支援あり・時間切れなら180秒とし、その3課題平均とする。これは実際に操作した平均時間そのものではなく、失敗を含めて比較するための事前定義した指標である。

参加者ごとに Enhanced - Baseline を計算し、その平均と参加者単位の百分位ブートストラップ95%区間（5000回、固定シード20260929）を求める。正答率差は正、時間差は負ならEnhanced側が良い方向である。参加者数1では区間を出さない。少数標本の区間は不安定で、確定的な母集団推論には使わない。

完了者の対応比較と、中断者数・欠測を併記する。6課題を6人分として扱わない。同じ参加者の記録を独立標本として増やさない。成功者だけの時間は参考値にとどめ、失敗を除いて「速くなった」と結論しない。

操作ログはカテゴリ・検索実行・詳細表示・出典リンク・リセットの件数である。全クリック数でも認知負荷でもない。検索語や外部サイトでの操作は記録しない。評価票は独自の質問であり、SUS等の標準尺度を名乗らない。
